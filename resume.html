Selected work

AI-Assisted Claims Recommendation — Proposal & PoC for an HR Platform

Solutioned and won a 2025 proposal for an AI-assisted claims-recommendation plugin for an HR platform — a rules + ML hybrid that recommends eligibility decisions on employee claims, with a demonstrated proof of concept.

Challenge
Claims on an HR platform — reimbursements, benefits, insurance — were reviewed manually against plan rules that vary by policy, geography and dependent status. The client wanted faster, more consistent decisions without losing governance: no black-box approvals, no silent rule drift. The proposal had to show an AI approach the business could defend.
My contribution
I led the proof of concept end to end and shaped the solution story: how the recommendation engine splits responsibility between deterministic rules and learned patterns, what the reviewer sees for each recommendation, how the plugin embeds in the existing HRP interface, and what it means operationally. I prepared the architecture diagrams for the proposal, and collaborated with the domain team on entitlement logic and with the sales team on how the case gets heard in the room.
Technical approach
The heart of the design is a deliberate split: a deterministic eligibility engine owns the hard constraints — plan rules, policy limits, dependent entitlements — and an ML recommendation layer sits on top for the judgement calls, learning from historical outcomes. Every recommendation arrives with its grounds — the rule that fired or the pattern that matched — so a reviewer can trust, correct and audit it. The PoC ran the recommendation flow inside the actual claims journey of the HRP UI, as a plugin rather than a separate portal.
Tools used
Deterministic rules engine · ML recommendation layer · explainable recommendation flow · HRP UI plugin PoC
Outcome
The proposal was won. The client's claims process now moves from manual review toward an explainable, AI-assisted decision flow — and the work was recognized with the Most Valuable Player award in the Architect category, 2025.

Cloud Onboarding — Remote Visualization for Lab Users

Evaluated the cloud onboarding and remote-visualization architecture for a chromatography data system used in scientific laboratories.

Challenge
Instrument data was tied to the bench: results were visible on the instrument itself, but lab users working elsewhere could not see them.
My contribution
I assessed how the software could be onboarded to a cloud environment and what a remote-visualization architecture would need to do for lab users.
Technical approach
I kept the onboarding of the instrument software separate from the movement of the instrument's own processing or control functions — onboarding the application to the cloud does not move the instrument's control loop — and defined the boundary between them before expressing the result as a technical proposal.
Tools used
React · graphql · golang · NATS · Nomad · Docker · Azure · cloud onboarding evaluation · remote-visualization architecture · chromatography data system assessment
Outcome
A defensible technical position for the client and their engineers: what could move to the cloud, what had to stay, and what the integration boundary looked like.

Architecture at Scale — Genetic-Testing Platform

Defined the frontend architecture for a genetic-testing platform processing very large volumes of scientific and diagnostic data.

Challenge
A standardized genetic platform had to serve both diagnostics and research workflows, with data volumes well beyond a conventional web application.
My contribution
I defined the frontend architecture for the platform, and how complex scientific workflows were represented in the interface.
Technical approach
The architecture separated presentation from the volume of the underlying data — deciding which data the frontend actually needed, and rendering that rather than the full dataset — so the interface stayed responsive while the platform's overall data scale kept growing.
Tools used
Nextjs · Redux · RestAPI · Java-Springboot · AWS · Volume-aware frontend architecture · presentation–data separation · scalable interface design
Outcome
A reusable frontend architecture that could absorb new tests, new workflows and new laboratories without rework.
